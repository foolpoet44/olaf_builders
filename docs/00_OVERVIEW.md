# 00. 개요

## 1. 무엇을 만드나

**OLAF Builders** — OLAF AXellerator 1기 참여자 32명(3개 Domain Lab · 7개 그룹)과 Master(코치)·사무국이
과제 해결과 역량 향상을 두고 이야기하고, 교육 자료를 보고, 질문을 모으는 **사내 전용 웹앱**.

| 사용자 | 규모 | 주 사용 |
|---|---|---|
| Builder (참여자) | 32명 | 교육 자료 열람 · 질문 카드 작성 · 커뮤니티 글·댓글 |
| Master (코치) | 수 명 | 담당 Lab 공간 읽기·쓰기 · Master Q&A 답변 |
| 사무국 (office) | 1~3명 | 명단·로그인 관리 · 자료 올리기/내리기 · 질문 카드 취합 · 공지 · 숨김 |

동시 접속은 수십 명 이하. 이 규모에서는 SQLite 파일 하나와 Node 프로세스 하나로 충분하다.

## 2. 왜 원점 재시작인가

기존 리포는 Vercel(서버리스) + Neon(클라우드 Postgres) + Upstash(KV)에서 운영하려고 만들어졌다.
사내 서버로 옮기려 하자 다음 문제가 겹쳤다.

| 문제 | 기존 리포 상태 |
|---|---|
| 서버리스 구조 | `api/*.py` 함수 클래스를 사내용 WSGI 덧대기(`olaf_app.py`)가 메모리 안에서 흉내 냄 · 개발용 단일 스레드 서버 |
| 저장소 다섯 갈래 | Neon HTTPS SQL · psycopg 직접 접속 · SQLite · Upstash KV · `bundle.json` + 로컬 감사 파일 |
| 이관 전용 코드 | `pg_transfer` · `pg_sql_export` · `audit_sync` · `rebuild_from_live` 등 십여 개 |
| 서버 선행 조건 | Python 3.11 설치 승인 + PostgreSQL 16 설치·계정·`pg_hba`·`pg_dump` 예약 작업 |
| 인증 층층 | 관리 토큰 + 공용 열람 코드 + 개인 코드 로그인 + 서명 키 2종 |

업무 기능 자체는 작다. **옮기는 비용이 다시 만드는 비용보다 크다**고 판단했다.

## 3. 목표

1. 서버에 **아무것도 설치하지 않고**(압축 해제만) 서비스로 띄운다.
2. **DB 관리가 사실상 없다** — 파일 하나, 백업은 앱이 스스로, 복원은 파일 교체.
3. **보안은 최소지만 실재한다** — 로그인·역할 검사·감사 기록·입력 검사. 그 이상은 승인 뒤 단계적으로.
4. 기존 업무 원칙(판정 금지·개인정보 최소·흔적 보존)은 그대로 지킨다.
5. `reference/DEPLOYMENT_ENVIRONMENT.md`의 배포 계약(별도 폴더·포트·서비스, 헬스 엔드포인트, 릴리스 분리)을 충족한다.

## 5. 용어

| 용어 | 뜻 |
|---|---|
| 케이스ID | Builder를 가리키는 키. selection_agent C29 파일 기준. C29 확정 전에는 임시 ID(`T-01` 등) |
| 내부 번호 | Master `MS-01`, 사무국 `OP-01` 형식 |

| 공유 폴더 | `C:\ProgramData\PRI\olaf-builders\` — 설정·데이터·업로드·로그·백업 |
