# 16. 학습자 온보딩 — 질문 카드 화면 점검 · 접속 안내문 · 계정 일괄 생성

작성: 2026-11-16 · 범위: 개발 PC 확인까지. 대상 서버 반영은 결정 B1~B5 회신 후 (`docs/11_DECISIONS.md`).
화면 개선안은 **제안**이다. 단계 밖 기능이므로 코드는 바꾸지 않았다(헌법 C절).

## 1. `qcard.html` 점검 결과 (참여자 계정으로 로그인 · 1280px / 390px)

확인한 것: 로그인 → 질문 카드 이동, 새 카드 폼, 실시간 낭독 문장 미리보기, 내 카드 목록, 모바일 폭.
**확인하지 않은 것:** 제출·수정·철회 실행, 3장 제한 도달, 제출 마감 상태, 검사 오류의 서버 응답 문구.

### 1-3. 여백·정렬 (사소)

- 세션 선택과 포맷 탭이 붙어 있다(위 여백 없음).
- `제출` 버튼이 미리보기 상자에 바짝 붙고, `내 카드` 제목이 폼 카드에 바짝 붙는다.
- 낭독 시간 `약 15초 / 40초`는 한도 대비 표시인데 한도 초과 시 색 변화 여부를 확인하지 못했다.
- 안내문의 `[ ]` 중 잠금 횟수는 설정값(10분 20회·IP 기준)으로 채웠고, 마감일·1인 장수는 사무국이 확정한다.

### 1-4. 데이터 쪽 발견

- 가져온 44장의 낭독 문장에는 빈 과제명 괄호가 들어 있고, 일부(2장)는 어미 중복도 있다. 원본 CSV의 `situation`이 이미 `…하려고 하는데` 형태다. **원본을 고치지 않고** 화면 쪽에서 다룬다(원칙 5: 흔적 보존).

## 2. 학습자 접속 안내문 (주소·계정 칸은 비워 둠)

```
[제목] OLAF AXellerator 1기 · OLAF Builders 접속 안내

OLAF Builders는 Domain Lab 질문 카드와 교육 자료를 모아 두는 사내 전용 사이트입니다.

1. 접속 주소  : http://[                    ]/
   - 사내 네트워크(사내 Wi-Fi·VPN)에서만 열립니다. 외부에서는 열리지 않습니다.
   - 즐겨찾기에 추가해 두세요.
2. 로그인     : 아이디와 비밀번호는 사무국이 별도로 전달합니다.
   - 처음 받은 비밀번호는 [  ] 까지 사용해 주세요. (비밀번호 변경 기능 유무: 사무국 확인 후 기재)
   - 같은 PC에서 연속으로 많이 틀리면 잠시 잠깁니다(현재 설정: 10분 안에 20회). 잠시 뒤 다시 시도해 주세요.
3. 질문 카드 제출
   - 메뉴 「질문 카드」 → 세션 선택 → 빈칸 채우기 또는 자유 질문
   - 마감: [      ]  · 1인 최대 [  ]장
   - 낭독 시간은 한도(40초) 안으로 맞춰 주세요. 쓰는 동안 미리보기에 문장이 나옵니다.
   - 제출 후에도 마감 전에는 수정·철회할 수 있습니다. 수정하면 새 판으로 남습니다.
4. 입력하지 말아 주세요
   - 사번, 이메일, 휴대전화 번호, 고객·협력사의 비공개 정보

   - 이 사이트는 순위·점수를 매기지 않습니다. 질문은 건수와 이름순으로만 정리됩니다.
   - 사무국은 운영을 위해 글을 숨기거나 이전 판을 볼 수 있으며, 이 행위는 기록으로 남습니다.
```

칸마다 근거가 되는 설정: 마감·장수 = `config/app.json` `qcards`·`sessions` · 잠금 횟수 = `auth.rateLimit`.

## 3. 학습자 계정 일괄 생성 절차

두 단계다. **사람 등록(명단)** 과 **로그인 정보 설정**은 따로 한다 — 앱은 이메일을 저장하지 않으므로 전달은 사람이 한다.

### 3-1. 명단 CSV 만들기

필수 열: `person_id, role, name, title, lab, group` · 선택 열: `assigned, challenge`

```csv
person_id,role,name,title,lab,group,challenge
T-PA-1-90,builder,홍길동,선임,PA,PA-1,
T-AA-2-90,builder,김가명,책임,AA,AA-2,
```

- `person_id`: 케이스 ID(`T-<Lab>-<그룹번호>-<번호>`). Master는 `MS-01`, 사무국은 `OP-01` 형식.
- **사번·이메일 열은 있어도 된다.** 가져올 때 열째로 버리고 알려 준다(`[알림] 저장하지 않고 버린 열: 사번, 이메일`) — 개발 PC에서 시험 확인함.
- 진단 값 열(`gap` `current` `required` 등)이 있으면 **파일 전체를 거부**한다.
- 사번 패턴(6~7자리 숫자)이 다른 칸에 섞여 있으면 저장을 거부한다.
- 실명단 파일은 **리포에 넣지 않는다.** 서버 PC의 데이터 폴더 밖 임시 위치에 두고, 끝나면 안전하게 지운다.

### 3-2. 시험 → 적용 (서버 PC · 사무국 계정)

```powershell
# 1) 시험 — 저장하지 않고 건수·오류만 본다
node tools\admin.js import-roster D:\...\roster.csv --actor OP-01 --dry-run
# 2) 오류가 0이면 적용 (오류가 하나라도 있으면 아무것도 저장되지 않는다)
node tools\admin.js import-roster D:\...\roster.csv --actor OP-01
```

환경변수는 서비스와 같은 `APP_DATA_DIR`을 쓴다(서비스 실행 중에도 안전). 적용·갱신은 `audit_log`에 `roster_import`로 남는다. 역할이 바뀐 사람은 `permission_change`로 따로 남는다.

### 3-3. 로그인 정보 설정 (사람마다)

```powershell
echo <임시비밀번호> | node tools\admin.js set-credentials T-PA-1-90 --username <아이디> --password-stdin --actor OP-01
```

- 아이디: 영문 소문자로 시작, 영문·숫자·`.`·`_`·`-` 3~32자. 대문자는 소문자로 바뀐다.
- 비밀번호: 10자 이상 · 영문+숫자+특수문자 모두 포함.
- 실행하면 그 사람의 **기존 세션이 모두 종료**된다 → 재설정에도 같은 명령을 쓴다.
- 비밀번호를 명령줄 인자로 주지 않는다(`--password-stdin`만). 셸 기록에 남기지 않도록 일회용 값을 쓰고 전달 후 폐기.
- 아이디·임시 비밀번호는 안내문과 **다른 채널**로 개인에게 전달한다.

### 3-4. 확인·정리

```powershell
node tools\admin.js list                          # 등록된 사람 확인 (순서: ID순)
node tools\admin.js deactivate <person_id> --actor OP-01   # 탈퇴·제외 (상태 변경, 행 삭제 아님)
```

로그인 확인은 학습자 1~2명 계정으로 `/login.html` → `/qcard.html` 이동까지. 인수 항목은 `docs/09_TESTING.md`.

### 3-5. 개발 PC에서 실제로 확인한 것 / 못 한 것

| 확인함 | 못 함 |
|---|---|
| 사번·이메일 열이 있는 CSV의 `--dry-run`: 열을 버리고 건수 표시 | 대량(26명 이상) 계정 생성 반복의 소요 시간 |
| 참여자 계정 `set-credentials` 후 브라우저 로그인 → 질문 카드 화면 | 서버 PC(PowerShell 5.1)에서의 실행 — 위 PowerShell 블록은 **개발 PC에서 bash로 확인한 명령을 옮긴 것**이며 실행해 보지 않았다 |
| 비밀번호 규칙·아이디 규칙 (소스 확인) | 사번 패턴 혼입·진단 열 포함 CSV 거부 동작 (소스 규칙만 확인, 이번에 실행하지 않음) |

**갱신(2026-11-17):** 한 번에 설정하는 명령 `node tools\admin.js import-credentials <person_id,username,password.csv> --actor OP-01 [--dry-run]`을 추가했다(결정 B12 — 아이디=이메일 앞부분, 초기 비밀번호=사번, 참여자만 규칙 완화). 하나라도 오류면 아무것도 저장하지 않고, 비밀번호는 출력·감사 기록에 남기지 않는다. CSV는 리포 밖에 두고 적용 직후 지운다.
