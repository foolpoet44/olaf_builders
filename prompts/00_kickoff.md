# 00 · 시작 지시 (코딩 에이전트에 첫 메시지로)

이 리포 루트의 `CLAUDE.md`를 먼저 읽고 모든 작업에 우선 적용하라. 이어서 `README.md`의 읽는 순서대로 `docs/00`~`docs/12`와 `reference/DEPLOYMENT_ENVIRONMENT.md`를 읽어라.

이것은 기존 `af-lab-community` 리포의 이관이 아니라 **새 프로젝트**다. 기존 리포의 코드를 복사하지 마라. 규칙은 `docs/12_LEGACY_MAP.md` 2절이 가리키는 범위만 참고한다.

고정 제약:
- Node.js LTS 22.13+ · ES 모듈 · 운영 의존성 `express`(5.x) 하나 · 네이티브 모듈 금지 · 빌드 단계 금지 · 테스트는 `node --test`.
- DB는 `node:sqlite` 하나, 스키마는 `docs/03_DATA_MODEL.md` 그대로.
- 데이터·업로드·설정·비밀은 환경변수 경로에만. 릴리스 폴더에 쓰지 않는다.
- 배포 대상은 사내 Windows PC. 배포 스크립트는 PowerShell 5.1. 대상 서버의 서비스·방화벽·계정은 직접 바꾸지 말고 스크립트·절차로만 제공한다.
- 비밀값·실데이터를 리포에 넣지 않는다. 테스트는 가짜 데이터(`TEST-001`)만.

진행 방식:
1. 먼저 구현 계획(파일 목록·순서·테스트)을 10줄 이내로 보고하라.
2. `prompts/P0_skeleton.md`를 수행하라. 이후 단계(`P1_to_P4.md` → `P4_5_to_P4_6_extensions.md`)는 내가 지시할 때만 진행한다. P0 스키마는 `001_init.sql`만 만든다(002·003은 확장 단계에서).
3. 단계 끝에 `npm test` 결과 요약, 요구사항 ID별 충족 여부, **미검증 범위**, `STATUS.md` 갱신 내용을 보고하라.
4. 문서와 다르게 구현해야 할 이유가 생기면 구현 전에 묻고, 합의되면 `docs/11_DECISIONS.md`에 ADR을 추가하라.
